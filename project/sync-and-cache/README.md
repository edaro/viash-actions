

# sync-and-cache

Sync and cache test resources. This action will sync test resources from
different sources (e.g. s3, gs, LaminDB) and cache them for later use.
The cache key is based on the hash of the test resources. For this
action to work, the Viash project config should contain a list of test
resources to sync.

Supported storage types:

- `s3`: Syncs resources from an S3 bucket.
- `gs`: Syncs resources from a Google Cloud Storage bucket.
- `lamin`: Syncs an artifact or the artifacts of a collection from a
  LaminDB instance.
- Create a GitHub issue if you need support for other storage types.

The type is inferred from the path if not specified. After syncing,
files under `dest` that do not belong to the resource are removed.

Example:

``` yaml
info:
  test_resources:
    - type: s3
      path: s3://my-bucket/my-folder
      dest: my-folder
    - type: gs
      path: gs://my-bucket/my-other-folder
      dest: my-other-folder
    - type: lamin
      path: lamin://my-org/my-instance/collection/abcdEFGH12345678
      dest: resources_test
    - path: lamin://my-org/my-instance/artifact/abcdEFGH123456780000
      dest: resources_test/common/pancreas/dataset.anndata.zarr
```

LaminDB resources:

- `path` has the form `lamin://<owner>/<instance>/artifact/<uid>` or
  `lamin://<owner>/<instance>/collection/<uid>`. A 20-character uid pins
  an exact version, a 16-character stem uid resolves to the latest
  version.
- An artifact (a file or a folder) is downloaded to exactly `dest`.
- Each artifact of a collection is downloaded to `<dest>/<key>`. Use the
  optional field `strip_prefix` to remove a prefix from the start of
  each key.
- The cache key is derived from the uids and hashes of the resolved
  artifacts and collections, so it changes exactly when their content
  changes.
- Public instances are read anonymously. For private instances, set the
  `LAMIN_API_KEY` environment variable.
- Requires [uv](https://docs.astral.sh/uv/), which is installed by this
  action if needed.

### Inputs

- `project_directory`: - *optional*. Path to the project directory. This
  is the directory where the project config `_viash.yaml` is located.
- `cache_key_prefix`: - *optional*. A prefix for the cache hash key.
  Prefix is also used for restoring stale cache if no cache hit occurred
  for key.

### Outputs

- `cache_key`: Caching key to use to restore the cache. If no test
  resources are detected, this will be an empty string.
- `dest_paths`: Paths to the synced resources. If no test resources are
  detected, this will be an empty string.
- `cache_hit`: `'true'` if the cache was restored from an exact match of
  `cache_key`, `'false'` otherwise.

## Examples

``` yaml
name: Demo of sync-and-cache

on:
  push:
  pull_request:

jobs:
  demo:
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v7

      - name: Sync and cache test resources specified by the project config
        uses: edaro/viash-actions/project/sync-and-cache@v7
```
